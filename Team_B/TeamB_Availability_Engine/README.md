# Team B — Appointment Scheduler Engine
## Availability Search & Conflict Analytics (dynamic input + generated API key)

This is a local Java 17 / Maven demo for Team B. It provides a browser form where a user can enter a provider ID, date, and appointment duration. The engine validates the request, finds free slots from its loaded calendar data, checks overlapping bookings, and returns JSON.

## Features
- Dynamic browser form served at `http://localhost:8080/`
- `GET /availability?provider=P12&date=2026-10-04&duration=30`
- Generated local API key using Java `SecureRandom`
- API key required in the `X-API-Key` request header
- Key is saved to `data/api-key.txt` so it remains stable across restarts; delete that file to generate a new key next start
- Public `GET /health` endpoint
- H2 database / JDBC persistence and demo appointment seed data
- Request validation, slot search/ranking, conflict analytics, JSON result builder
- JUnit tests

## Requirements
- Java 17 or newer
- Maven 3.9+ (internet access on first build may be needed to download dependencies)

## Run on Windows
1. Extract the ZIP file.
2. Open Command Prompt or PowerShell in the extracted `TeamB_Availability_Engine` folder.
3. Run:

```powershell
mvn clean test
mvn compile
mvn exec:java -Dexec.mainClass="com.teamb.scheduler.Main"
```

4. Look in the terminal for `Generated/reused API key (keep private): ...`.
5. Open `http://localhost:8080/` in your browser.
6. Paste the API key into the form, enter provider ID, date and duration, then click **Find available slots**.

## API usage outside the browser
Use the generated key from `data/api-key.txt` as the `X-API-Key` header:

```bash
curl -H "X-API-Key: YOUR_LOCAL_KEY" "http://localhost:8080/availability?provider=P12&date=2026-10-04&duration=30"
```

Health check (no key required):

```bash
curl http://localhost:8080/health
```

## API key notes
- This is a key generated by this local demo to protect its `/availability` endpoint. It is **not** an OpenAI, Google, or other third-party API key.
- The key is generated automatically on first run and stored in `data/api-key.txt`. It is excluded from Git by `.gitignore`.
- Keep it private. This basic demo is intended for localhost/classroom use, not direct public internet deployment. For production, use HTTPS, proper secret storage, rate limiting, and stronger authentication/authorization.

## Current demo data and limitations
- The H2 database seeds sample bookings for provider `P12` and `P20` on `2026-10-04` when the appointments table is empty.
- Working hours in the demo search logic are 09:00–17:00.
- The interval index is a sorted list implementation; a balanced AVL/Red-Black interval tree is not implemented in this version.
- The engine loads appointment data into its index at startup. If you change the database while the server is running, restart the app to refresh the index.
- This version accepts dynamic search parameters; it does not provide an appointment-booking endpoint.
